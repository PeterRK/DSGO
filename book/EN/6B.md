# Prim's Algorithm
　　Unlike Kruskal's algorithm, Prim's algorithm starts from vertices. We divide the vertices in the graph into two parts: the main group and the outer area. Then we repeatedly select, from the outer area, the vertex that is currently closest to the main group and absorb it into the main group, until the main group contains all vertices.

## Plain Implementation
　　We need to record some state information for vertices, including the nearest vertex already in the main group and the distance to it.
```go
type vertex struct {
    idx  int    //the id of this vertex
    link int    //the id of the associated vertex
    dist uint   //distance to the associated vertex
}
```
　　Initially, we mark all vertices as unreachable, and then start from one vertex and gradually expand the territory. Each time a vertex is absorbed, we update the information of the neighboring outer vertices. With an adjacency matrix as input, the complexity is `O(V<sup>2</sup>)`.
```go
func PlainPrim(matrix [][]uint) (uint, error) {
    //...
    memo := make([]vertex, size)
    for i := 0; i < size; i++ {
        memo[i].idx, memo[i].dist = i, math.MaxUint         //all unreachable at first
    }
    memo[size-1].dist = 0

    for last := size - 1; last > 0; last-- {
        best := 0
        for i := 0; i < last; i++ {
            dist := matrix[memo[last].idx][memo[i].idx]
            if dist != 0 && dist < memo[i].dist {
                memo[i].dist = dist                         //update distance from outer vertex to main group
            } else {
                dist = memo[i].dist
            }
            if dist < memo[best].dist {
                best = i                                    //find the closest outer vertex
            }
        }
        if memo[best].dist == math.MaxUint {                //cannot connect all vertices
            return 0, errors.New("isolated part exist")
        }
        sum += memo[best].dist
        memo[best], memo[last-1] = memo[last-1], memo[best] //absorb the closest outer vertex into the main group
    }
    return sum, nil
}
```

## Heap Optimization
　　Prim's algorithm is essentially performing a special kind of breadth-first search (when all edge weights are equal, it degenerates into ordinary breadth-first search). With adjacency lists as input, we can use the pairing heap discussed in the previous chapter to optimize the algorithm:
```go
func Prim(roads [][]graph.Path) (uint, error) {
    //...
    const fakeIdx = -1
    nodes := make([]pheap.NodeG[vertex], size)                  //allocate nodes in an array for easy lookup
    for i := 1; i < size; i++ {
        nodes[i].Val = vertex{idx: i, link: fakeIdx, dist: 0}   //all start as untouched
    }
    nodes[0].Val = vertex{idx: 0, link: 0, dist: 0}
    hp := pheap.New(nearer)
    hp.Push(&nodes[0])

    var cnt int
    for cnt = 0; !hp.IsEmpty(); cnt++ {
        curr := hp.Pop()
        sum += curr.Val.dist
        idx := curr.Val.idx
        curr.Val.idx = fakeIdx                                  //remove from outer area and absorb into main group
        for _, path := range roads[idx] {
            peer := &nodes[path.Next]
            if peer.Val.link == fakeIdx {                       //untouched vertex, move into outer area
                peer.Val.link = idx
                peer.Val.dist = path.Weight
                hp.Push(peer)
            } else if peer.Val.idx != fakeIdx &&                //outer vertex
                path.Weight < peer.Val.dist {                   //needs adjustment
                peer.Val.link = idx                             //update nearest neighbor
                peer.Val.dist = path.Weight
                hp.FloatUp(peer)
    }   }   }
    if cnt != size { return sum, errors.New("isolated part exist") }
    return sum, nil
}
```
　　The optimized implementation has two layers of traversal:

　　• Repeatedly popping elements from the heap, which is equivalent to traversing vertices.

　　• Traversing all edges step by step, adding elements into the heap or adjusting the remaining elements already inside it.

　　From the properties of the pairing heap, we know that the former costs `O(VlogV)`, while the latter costs `O(E)`. Therefore, the overall complexity is `O(VlogV + E)`. A pairing heap is especially suitable here because the "nearest neighbor" of an outer vertex may be rewritten again and again, and `FloatUp` matches exactly this kind of decrease-key operation.
