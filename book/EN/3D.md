# Perfect Hashing
　　For a fixed data set, we can always find a hash function that maps it into a table whose capacity is at least the number of elements in the set. This situation is called perfect hashing.

## The BDZ Algorithm
　　The core idea of the BDZ algorithm is to try different hash seeds until it finds a collision-free filling pattern for a multi-way hash table.

```go
func (h *bdz) init(keys []string) bool {
    //...
    for trys := 0; trys < 8; trys++ {
        h.seed = rand32()
        if !graph.init(keys, h.hash) { //generate the hypergraph from the random seed
            return false
        }
        array.SetAll(bitmap[:ebmSize], 0)
        free = graph.tear(free, bitmap) //tear down the hypergraph to get the edge sequence
        if len(free) != len(graph.edges) {
            continue
        }
        array.SetAll(bitmap[:nbmSize], 0)
        h.mapping(graph.edges, free, bitmap)
        return true
    }
    return false
}
```
　　In practical implementations, a three-way hash table is usually used. If we take table slots as vertices and elements as edges, the structure becomes a kind of hypergraph.

```go
type vertex struct {   //linked-list body
    slot uint32
    next uint32
}
type list struct {     //linked-list head
    size uint8
    head uint32
}
type hypergraph struct {
    edges [][3]vertex //hypergraph edges, each edge has three vertices
    nodes []list      //hypergraph vertices, represented as linked lists
}

func (g *hypergraph) init(keys []string, hash func(string) [3]uint32) bool {
    array.SetAll(g.nodes, list{0, endIdx})
    for i := 0; i < len(keys); i++ {
        slots := hash(keys[i])
        for j := 0; j < 3; j++ {
            v := &g.edges[i][j]
            v.slot = slots[j]
            n := &g.nodes[v.slot]
            v.next = n.head
            n.head = uint32(i)
            n.size++
            if n.size > 50 { //abnormal clustering
                return false
    }   }   }
    return true
}
```
　　This transforms the problem from "how do we place elements into slots?" into "can this hypergraph be peeled away completely?" If it can, then there exists a collision-free arrangement.

　　During the process of tearing the hypergraph down, ensuring that each removed edge genuinely frees at least one vertex means that the corresponding element in the multi-way hash table can obtain a slot.

```go
func (g *hypergraph) tear(free []uint32, bitmap []uint32) []uint32 {
    free, head := free[:0], 0
    for i := 0; i < len(g.edges); i++ {
        for j := 0; j < 3; j++ {
            n := g.nodes[g.edges[i][j].slot]
            if n.size == 1 && testAndSetBit(bitmap, n.head) {
                free = append(free, n.head)
                break
    }   }   }
    for head < len(free) {
        curr := free[head]
        head++
        for j := 0; j < 3; j++ {
            v := &g.edges[curr][j]
            n := &g.nodes[v.slot]
            p := &n.head
            for *p != curr {
                p = &g.edges[*p][j].next
            }
            *p = v.next
            v.next = endIdx
            n.size--
            if n.size == 1 && testAndSetBit(bitmap, n.head) {
                free = append(free, n.head)
    }   }   }
    return free
}
```
　　When actual values are assigned, the filling must proceed in reverse order of the tear-down sequence. Only then does each step still retain at least one candidate slot that has not yet been occupied, so the mapping process will not walk itself into a dead end.
