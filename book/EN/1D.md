# Radix Sort
　　Radix sort follows a different idea from the sorting algorithms above and does not rely on comparison. Here we count the distribution of data by digit and then rearrange the data according to that distribution. Repeating this process from the low-order bits to the high-order bits eventually produces a globally ordered sequence.

```go
func RadixSort[T constraints.Integer](list []T) {
    byteWidth := uint(unsafe.Sizeof(T(0)))
    bitWidth := byteWidth*8
    base := T(1) << (bitWidth - 1)
    signed := (base>>bitWidth) != 0
    size := len(list)
    temp := make([]T, size)
    
    if signed {
        for i := 0; i < size; i++ { list[i] += base }       //turn int into uint
    }

    const bk = 1 << 8
    var memo [bk]int                                        //count table
    for step := uint(0); step < bitWidth; step += 8 {
        for i := 0; i < bk; i++ {
            memo[i] = 0
        }
        for i := 0; i < size; i++ {
            radix := uint8(list[i] >> step)
            memo[radix]++                                   //count digit distribution
        }
        off := 0
        for i := 0; i < bk; i++ {
            memo[i], off = off, off+memo[i]                 //turn counts into offsets
        }
        for i := 0; i < size; i++ {
            radix := uint8(list[i] >> step)
            temp[memo[radix]] = list[i]                     //place into bucket order
            memo[radix]++
        }
        list, temp = temp, list
    }
    
    if byteWidth % 2 == 0 {
        if signed {
            for i := 0; i < size; i++ { list[i] -= base }   //turn uint back into int
        }
    } else {
        if signed {
            for i := 0; i < size; i++ { list[i] = temp[i] - base }
        } else {
            copy(list, temp)
}   }   }
```
　　The implementation above processes 8 bits per round, which is to say one stable "bucket and refill" pass per byte. Once the low-order bytes have been ordered, later passes on higher-order bytes no longer destroy the relative order already established below, so after enough rounds the entire sequence becomes ordered.

　　For signed integers, the code first shifts the values into an unsigned space before sorting, and shifts them back afterward. This neatly avoids trouble caused by the sign bit without changing the numerical order.

## Characteristics and Limitations
　　Radix sort needs `O(N+2^m)` extra space, where `m` is the digit width of the radix. Its time complexity is `O((w/m)N)`, where `w` is the bit width of the data. Since `m` is usually just a small constant, its practical space cost is not very different from merge sort. It is also stable.  
　　Radix sort has an advantage in time complexity, but it requires the data to be splittable into digits, whereas the sorting algorithms introduced earlier require only comparability. In real applications, that requirement is often hard to satisfy. Even ordinary signed integers do not fit directly (though they can be converted into unsigned form first). This greatly limits the range of situations in which radix sort is truly suitable.
