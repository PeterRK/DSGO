# Dijkstra's Algorithm
　　Dijkstra's algorithm is a classical algorithm for finding single-source shortest paths. Its idea is consistent with the Prim algorithm discussed in the previous section. The difference is that the vertex selected from the outer area each time is no longer the one closest to the main group, but the one closest to the source vertex.

## Implementation & Analysis
　　The implementation of Dijkstra's algorithm is very similar to that of Prim's algorithm. It can likewise be optimized with a heap, and its time complexity is also `O(VlogV + E)`.

　　The real difference between the two lies only in the meaning of "distance": Prim maintains the shortest connecting edge from a vertex to the main group, while Dijkstra maintains the current shortest path length from a vertex to the source.
```go
func DijkstraPath(roads [][]graph.Path, start, end int) []int {
    //...
    for !hp.IsEmpty() {
        curr := hp.Top()
        idx := curr.Val.idx
        if idx == end { return trace() }                    //return the shortest path
        curr.Val.idx = fakeIdx                              //remove from outer area and absorb into main group
        hp.Pop()
        for _, path := range roads[idx] {
            peer := &nodes[path.Next]
            if peer.Val.link == fakeIdx {                   //untouched vertex, move into outer area
                peer.Val.link = idx
                peer.Val.dist = curr.Val.dist + path.Weight
                hp.Push(peer)
            } else if peer.Val.idx != fakeIdx {             //outer vertex
                dist := curr.Val.dist + path.Weight
                if dist < peer.Val.dist {                   //needs adjustment
                    peer.Val.link = idx                     //update nearest predecessor
                    peer.Val.dist = dist
                    hp.FloatUp(peer)
    }   }   }   }
    return nil
}
```

## Following Intuition
　　Sometimes we only need one path and do not insist that it be the shortest. In that case, intuition may help us find an answer more quickly.
```go
for _, path := range roads[idx] {
    peer := &nodes[path.Next]
    if peer.Val.link == fakeIdx {
        peer.Val.link = idx
        peer.Val.dist = curr.Val.dist + path.Weight
        //dist records the distance from the start to the current vertex,
        //evaluate estimates the distance from the current vertex to the destination
        peer.Val.weight = peer.Val.dist + evaluate(peer.idx)    //reason + intuition
        hp.Push(peer)                                           //used as the selection criterion
    } else if peer.Val.idx != fakeIdx {
        dist := curr.Val.dist + path.Weight
        if dist < peer.Val.dist {
            peer.Val.link = idx
            peer.Val.weight -= peer.Val.dist - dist
            peer.Val.dist = dist
            hp.FloatUp(peer)
}   }   }
```

## Man Proposes, Heaven Disposes
　　Judging from time complexity, Dijkstra's algorithm is very strong when edge weights are non-negative. Real situations, however, are not so ideal.

　　The `DijkstraPath` implementation shown here actually uses a binary heap, because it cares more about reaching the destination quickly than about frequent decrease-key operations, unlike the full-distance version.
