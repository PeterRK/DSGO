　　A graph is a logical structure used to represent relations among vertices. Linked lists and trees can both be regarded as special kinds of graphs. Naturally, we can also use linked structures similar to theirs to represent graphs so that the storage structure matches the logical structure. In many situations, however, we only care about the logical structure, and therefore prefer to store graphs with arrays.

　　An adjacency matrix uses an `N×N` two-dimensional array to represent the edge between any two vertices, and usually reserves a special value to mean that an edge does not exist.
```go
type AdjMatrix [][]uint     //adjacency matrix
```
　　For sparse graphs, where the number of edges is small, an adjacency matrix wastes too much space, so adjacency lists are used instead. An adjacency list is also a two-dimensional structure, but in the second dimension it stores only the edges that actually exist, thereby saving space (and also reducing traversal cost).
```go
type Path struct {
    Next   int              //the other endpoint of the edge
    Weight uint
}
type AdjList [][]Path       //adjacency list (it can also be implemented as an array-list hybrid)
```
　　In some cases, we also directly use a one-dimensional array that stores a set of edges:
```go
type Edge struct {
    A, B   int              //the two endpoints of the edge
    Weight uint
}
type EdgeSet []Edge         //edge set
```

## Directed Acyclic Graphs (DAGs)
　　When a directed graph contains no cycle, we can extract from it an order in which no element depends on any element that comes after it. The process of extracting such an order is called **topological sorting**.
```go
func TopologicalSort(roads [][]int) ([]int, error) {
    size := len(roads)
    list := make([]int, 0, size)
    book := make([]int, size)
    for i := 0; i < size; i++ {
        for _, next := range roads[i] {
            book[next]++                //record how many upstream vertices exist
    }   }
    free := deque.NewQueue[int]()
    for i := 0; i < size; i++ {
        if book[i] == 0 {
            free.Push(i)                //the farthest-upstream vertices
    }   }
    for !free.IsEmpty() {
        curr := free.Pop()
        for _, next := range roads[curr] {
            book[next]--
            if book[next] == 0 {
                free.Push(next)
        }   }
        list = append(list, curr)
    }
    if len(list) != size { return nil, errors.New("loops exist") }
    return list, nil
}
```
　　This implementation peels vertices away starting from those whose indegree is zero, so it not only produces a topological order, but also conveniently checks whether a cycle still remains in the graph.

## Minimum Spanning Tree Problem
　　A tree is a special kind of graph. Its special property is that it connects all vertices using the fewest possible edges. In an undirected connected graph, we can obviously find one or more trees that contain all vertices (that is, spanning trees), and the minimum spanning tree problem asks for the one whose edge weights sum to the smallest value.  
　　For this problem, we will discuss Kruskal's algorithm and Prim's algorithm. The former leans toward "looking at edges first", while the latter leans toward "claiming vertices first".

## Shortest Path Problem
　　As the name suggests, the shortest path problem seeks a path between vertices whose total edge weight is minimal.  
　　For this problem, we will discuss Dijkstra's algorithm and SPFA. Their main difference is whether they can handle negative edge weights, and whether they are willing to give up some practical efficiency for theoretical guarantees.

## Maximum Flow Problem
　　In the previous two problems, edge weights are treated as additive quantities such as distance. In a pipeline network, however, the weight of an edge often represents the upper limit of flow. The maximum flow problem asks us to analyze the maximum amount of flow that can pass between two vertices in such a network.  
　　For this problem, we will discuss Dinic's algorithm based on the Ford-Fulkerson method.
