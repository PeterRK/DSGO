# Bloom Filters
　　In the previous section we discussed reducing collisions by using multiple hash functions. This section pushes that idea to the extreme.

## Bit Vectors
　　The core structure of a Bloom filter is a bit vector, that is, an array of bits. Since the smallest addressable unit of storage is a byte, we need some extra operations layered on top of a byte array to implement bit-vector behavior.

```go
type Bitmap struct {
    core [VecSize]byte          //bit vector
}
func (tb *Bitmap) setBit(pos uint) {
    tb.core[pos>>3] |= (byte(1) << (pos & 7))
}
func (tb *Bitmap) testBit(pos uint) bool {
    bit := tb.core[pos>>3] & (byte(1) << (pos & 7))
    return bit != byte(0)
}
```

## Many Hashes, One Table
　　A Bloom filter uses multiple hash functions, but not multiple hash tables. Each hash merely marks one bit in the same table. By checking whether all hash results of an element are marked, we can infer whether that element has been registered. This is obviously not rigorous: it allows a certain probability of false positives, though false negatives do not occur. The false-positive rate `p` is related to the load factor `n/m` (`n` is the number of elements, `m` is the table capacity):

　　The version in the repository takes 8 hash routes at a time, first uses an extra result to choose one shard, and then marks bits within that shard. This means expansion can be done by increasing the number of shards instead of globally rearranging old marks.

```
The probability that an element is falsely judged present is the probability that all positions pointed to by its hash routes have already been marked. Suppose there are x hash routes, then
p = (1 - (1 - 1/m)^(nx))^x
From ln(1+x) = x - x^2/2 + x^3/3 - x^4/4 +... we know that when m is large, ln(1-1/m) ≈ -1/m
So (1-1/m)^m = e^(m ln(1-1/m)) = 1/e, and hence
p = (1 - 1/e^ax)^x, where a = n/m
Let y = 1/e^ax, then p = (1-y) ^ -ln(y)/a
Differentiating p(y), we obtain p' = ((1-y) ^ -ln(y)/a)(ln(y)/(1-y) - ln(1-y)/(y)) / a
Since x is a positive integer and a is positive, y ∈ (0,1)
The sign of p' is determined by f = ln(y)/(1-y) - ln(1-y)/(y)
And since f' = ((1-y)/y + ln(y))/(1-y)^2 + (y/(1-y) + ln(1-y))/y^2 > 0, f is monotonically increasing
Therefore, when y∈(0,1/2), p'<0, and when y∈(1/2,1), p'>0
It follows that p reaches its minimum at y=1/2, namely 1/2^(ln(2)/a)
At that point the optimal number of hash routes is x = ln(2)/a, and conversely from the false-positive rate we can infer the load factor n/m = a = (ln(2))^2/(-ln(p))
If p = 1/2^w, then n/m = ln(2)/w ≈ 0.7/w
```
　　When the load factor is `1/10`, the expected false-positive rate `p` is about `1/120`; when the load factor is `1/20`, `p` drops to about `1/15000`.

　　So a Bloom filter is well suited to the job of "coarse screening first." It can very cheaply rule out large numbers of nonexistent targets, but whenever it says "possibly present," a real hash table or some other structure will usually still have to confirm it.
