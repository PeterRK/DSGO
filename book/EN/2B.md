# Block Lists
　　The previous section exposed the weakness of linked lists relative to arrays in access efficiency. This section responds by absorbing arrays into the structure and using them to renovate the traditional list. At that point, a list node no longer carries a single element, but an array.

```go
type piece[T any] struct {
    fw, bw *piece[T]
    data   [PieceSize]T
}
```
　　This is essentially using arrays to dilute the pointer overhead of a linked list. One jump no longer buys only one element, but an entire chunk of contiguous storage, and sequential access therefore enjoys much better locality.

## Deques
　　A block list strengthens sequential-access performance while preserving the convenience of easy growth, which makes it well suited for building a deque. In fact, the construction is quite simple: just add two cursors.
```go
type deque[T any] struct {
    f, b struct {         //cursors
        p *piece[T]
        i int
    }
    size int
}

func (dq *deque[T]) reset(block *piece[T]) {
    dq.size = 0
    block.fw, block.bw = nil, nil
    dq.f.p, dq.b.p = block, block
    dq.f.i, dq.b.i = PieceSize/2, PieceSize/2-1
}

func (dq *deque[T]) init() {
    dq.reset(new(piece[T]))
}
```
　　These two cursors both grow outward from the middle, so in the initial state both the front side and the back side keep some spare buffer room, which reduces the number of block expansions.

　　The main operations of a deque are insertion and popping:

```go
func (dq *deque[T]) PushFront(unit T) {
    if dq.f.i == PieceSize {           //cross boundary
        dq.f.i = 0
        if dq.f.p.fw == nil {          //expand
            block := new(piece[T])
            block.bw, block.fw = dq.f.p, nil
            dq.f.p.fw = block
        }
        dq.f.p = dq.f.p.fw
    }
    dq.f.p.data[dq.f.i] = unit
    dq.f.i++
    dq.size++
}

func (dq *deque[T]) PopFront() T {
    if dq.IsEmpty() {
        panic("empty deque")
    }
    dq.size--
    dq.f.i--
    unit := dq.f.p.data[dq.f.i]
    if dq.f.i == 0 {                    //cross boundary
        dq.f.i = PieceSize              //dq.f.idx is never 0
        dq.f.p.fw = nil                 //keep only one spare block
        dq.f.p = dq.f.p.bw
    }
    return unit
}

//PushBack and PopBack are similar
```
　　Only when one end crosses the boundary of the current block does the implementation allocate or switch to a neighboring block; and on the way back, it keeps only one spare block. This keeps it from doing the large bulk moves of a pure array, while also avoiding the extreme scattering of a naive linked list.
