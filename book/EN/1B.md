# Merge Sort

　　The greatest weakness of insertion sort is the repeated movement caused by continuous insertion. Merge sort inherits the basic idea behind insertion sort, but overcomes that problem.

## Merging
　　Continuously inserting several numbers into a sequence is, in effect, equivalent to merging the sequence formed by those numbers into the target sequence. This process of combining multiple sequences into one is called merging. If the participating sequences are already ordered, then with some extra space the merge itself can be completed in one pass.

```go
func merge[T cmp.Ordered](in1, in2, out []T) {
    i, j, k := 0, 0, 0
    for ; i < len(in1) && j < len(in2); k++ {
        if in1[i] <= in2[j] {
            out[k] = in1[i]; i++
        } else {
            out[k] = in2[j]; j++
        }
    }
    for ; i < len(in1); k++ {
        out[k] = in1[i]; i++
    }
    for ; j < len(in2); k++ {
        out[k] = in2[j]; j++
}   }
```
　　Notice that when `in1[i] <= in2[j]`, the left element is taken first. Therefore, even when equal elements exist, the relative order of elements inside the left subsequence is preserved, and that is exactly where the stability of merge sort comes from.

## Divide and Conquer
　　Now we only have to ask where the two ordered subsequences come from. The answer is divide and conquer: split one sequence into two, two into four, and so on, until the pieces are small enough, then solve the tiny cases with insertion sort.

```go
func mergeSort[T cmp.Ordered](a, b []T) {
    if size = len(a); size < lowerBound {
        InsertSort(a, b)
    } else {
        half := size / 2
        mergeSort(b[:half], a[:half])
        mergeSort(b[half:], a[half:])
        merge(a[:half], a[half:], b)
}   }
```
　　The implementation in the repository adds two practical refinements. First, small ranges fall back directly to a simple sort so that recursion does not go deeper than necessary. Second, during recursion, `a` and `b` take turns serving as input and output, which avoids allocating a fresh buffer on every level.

## Strengths and Weaknesses
　　Merge sort deserves credit for being very fast. It preserves insertion sort's good tradition of `O(NlogN)` comparisons, while also reducing movement cost to `O(NlogN)`. In addition, merge sort preserves the natural order of equal elements, which is another valuable property.  
　　Its weakness on arrays is equally obvious: it needs `O(N)` extra space. On the other hand, merge sort accesses space only in a one-way manner, which makes it particularly attractive for external storage devices with large capacity but poor random-access performance.
