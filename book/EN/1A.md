# Basic Sorting
　　Very often we want an ordered array, and that means sorting. Although the core actions of sorting are only comparison and movement, there are many ways to play the game.

## Bubble Sort
　　Bubble sort approaches the problem from the movement side. Its idea is extremely simple: move elements toward more suitable positions, one step at a time, until no further motion is possible. In real life, lining up for morning exercises often works that way as well: look at the person beside you, swap if necessary, and eventually the taller students drift toward the back. Bubbles rising in water while pebbles sink gives much the same feeling.
```go
func BubleSort[T cmp.Ordered](list []T) {
    for i := 0; i < len(list)-1; i++ {
        for j := len(list) - 1; j > i; j-- {
            if list[j] < list[j-1] {
                list[j], list[j-1] = list[j-1], list[j] //swap when unsuitable
}   }   }   }
```
　　Bubble sort looks concise, but in fact it suffers badly from short-sightedness, so both the number of comparisons and the number of moves reach `O(N<sup>2</sup>)`.

　　Still, it is not entirely without merit. Because bubble sort only swaps adjacent inverted elements, equal elements never have their relative order disturbed. In other words, it is a stable sort. The trouble is that this stability comes at too high a cost to be very valuable once the input grows beyond toy size.

## Selection Sort
　　Selection sort approaches the problem from the comparison side. Its idea is also simple: each time, select the most suitable remaining element and place it into the next position, until the whole line is built.
```go
func SelectSort[T cmp.Ordered](list []T) {
    for i := 0; i < len(list)-1; i++ {
        pos := i
        for j := i + 1; j < len(list); j++ {
            if list[j] < list[pos] {
                pos = j                                 //find the best
        }   }
        list[pos], list[i] = list[i], list[pos]
}   }
```
　　After all that careful picking, selection sort manages to limit the number of moves to `O(N)`, but the number of comparisons still reaches `O(N<sup>2</sup>)`. It really is a case of gaining one thing at the expense of another.

　　Unlike bubble sort, selection sort is usually unstable. The reason is that the newly selected "best candidate" may jump directly to the front, crossing over several equal elements on the way and thus disturbing their original order. That is acceptable when only the key value matters, but once elements carry additional information, the side effect becomes harder to ignore.

## Insertion Sort
　　Like selection sort, insertion sort divides the data into an ordered part and an unordered part. The difference is that selection sort leaves a hole and looks for someone to fill it, while insertion sort lets someone arrive first and then looks for the hole.
```go
func InsertSort[T cmp.Ordered](list []T) {
    for i := 1; i < len(list); i++ {
        key := list[i]
        a, b := 0, i
        for a < b {                                     //binary search
            m := a + (b-a)/2
            if key < list[m] {
                b = m
            } else {
                a = m + 1
            }
        }
        for j := i; j > a; j-- {
            list[j] = list[j-1]                         //make a hole
        }
        list[a] = key                                   //move in
}   }
```
　　With the help of binary search, insertion sort reduces the number of comparisons to `O(NlogN)`. Unfortunately, in the worst case the number of moves still remains `O(N<sup>2</sup>)`. Its average number of moves, however, is only about half the worst case, which is why insertion sort is usually faster in practice than selection sort.

　　Insertion sort is stable too, because a new element is inserted before the first element strictly greater than it, rather than jumping over elements equal to it. Equal elements therefore retain their original order. This property will return later in merge sort and radix sort, because stability is often a useful building block for more complicated algorithms.
```go
func SimpleSort[T cmp.Ordered](list []T) {      //a variant of InsertSort
    if len(list) < 2 { return }
    for i := 1; i < len(list); i++ {
        key := list[i]
        if key < list[0] {
            for j := i; j > 0; j-- {
                list[j] = list[j-1]
            }
            list[0] = key
        } else {
            pos := i
            for ; list[pos-1] > key; pos-- {            //O(n^2) comparisons
                list[pos] = list[pos-1]                 //comparison and move fused
            }
            list[pos] = key
}   }   }
```
　　If we do not insist too rigidly on the formal order of the comparison operation, we can combine comparison and movement more cleverly, and on small inputs this is usually faster.

　　This is also a very common engineering idea. Theoretically, the binary-search version of insertion sort reduces the number of comparisons; but on tiny arrays, a tighter loop with less control logic often wins instead. That is why the auxiliary code keeps a variant such as `SimpleSort`, and later introsort and merge sort will also fall back to a simple sort on small ranges rather than stubbornly adhering to a single "theoretically superior" method.

## Summary
　　These three sorting algorithms reflect three important ideas in sorting, and later merge sort, quicksort, and heap sort will develop them further.
