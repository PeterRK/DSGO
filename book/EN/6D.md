# SPFA
　　If edge weights can be negative, then repeatedly passing through certain edges may be beneficial. In that case, Dijkstra's "once selected, selected forever" principle no longer satisfies the requirements.

　　Let us first look at the Floyd-Warshall algorithm. It updates values in an alluvial-sand style of iterative refinement, with complexity `O(V<sup>3</sup>)`.
```go
    func FloydWarshall(matrix [][]int) {
        size := len(matrix)
        for k := 0; k < size; k++ {
            for i := 0; i < size; i++ {
                for j := 0; j < size; j++ {
                    if matrix[i][k] != MAX_DIST && matrix[k][j] != MAX_DIST {
                        distance := matrix[i][k] + matrix[k][j]
                        if distance < matrix[i][j] {
                            matrix[i][j] = distance
    }   }   }   }   }   }
```

## Precision Strikes
　　The weakness of Floyd-Warshall is obvious: it performs a large number of unnecessary exploratory updates.  
　　From Dijkstra's algorithm, we can see one fact: a vertex can change only if it is adjacent to another vertex that has just changed. Therefore, SPFA uses a queue to record changed vertices and carry out precision strikes.
```go
func SPFA(roads [][]graph.PathS, start int) ([]int, error) {
    size := len(roads)
    if size == 0 || start < 0 || start >= size {
        return nil, errors.New("illegal input")
    }

    q := array.NewQueue[int](size)
    dist := make([]int, size)                   //records the shortest distance to each vertex
    age := make([]int, size)                    //absolute value records enqueue count
    for i := 0; i < size; i++ {
        dist[i], age[i] = math.MaxInt, 0        //all unreachable at first
    }

    q.Push(start)
    dist[start], age[start] = 0, -1             //negative means currently in the queue
    for !q.IsEmpty() {
        curr := q.Pop()
        age[curr] = -age[curr]
        for _, path := range roads[curr] {
            distance := dist[curr] + path.Weight
            peer := path.Next
            if distance < dist[peer] {
                dist[peer] = distance
                if age[peer] >= 0 {             //not in the queue
                    q.Push(peer)
                    age[peer]++
                    if age[peer] > size {       //too many enqueues means a negative cycle must exist
                        return nil, errors.New("bad loops exist")
                    }
                    age[peer] = -age[peer]      //enqueue
    }   }   }   }
    return dist, nil
}
```
　　Here the code uses `age` to record both "whether the vertex is in the queue" and "how many times it has entered the queue". Once the enqueue count of some vertex exceeds the number of vertices, we can conclude that the graph contains a negative cycle from which one can profit repeatedly.

## Performance Analysis
　　The complexity of SPFA depends on how many times vertices enter the queue. Every time a vertex is enqueued, the edges connected to it will be traversed. In the worst case, every edge may be traversed `(V-1)` times, yielding `O(VE)`. In practical use, however, as we also saw in the previous section, the running time is often far below that theoretical upper bound.
