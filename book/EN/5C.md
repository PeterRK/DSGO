# Pairing Heaps
　　For heaps, the most important task is really handling the convergence of ordered chains. As the previous section showed, merging is the key operation in that process.

　　In a binomial heap, merging subtrees already costs only `O(1)`, so we can take that idea further. First, we remove the `2<sup>k</sup>` node-count restriction and allow a tree to contain any number of nodes. Second, to make node deletion easier, we add a backward pointer as well.
```go
type Node[T cmp.Ordered] struct {
    key   T
    child *Node[T]
    prev  *Node[T]  //parent or elder sibling
    next  *Node[T]  //younger sibling
}
```
　　We give up structural neatness and obtain an `O(1)` merge operation:
```go
func merge[T cmp.Ordered](master, slave *Node[T]) *Node[T] {
    if master.key > slave.key {
        master, slave = slave, master
    }
    slave.next = slave.hook(master.child)
    master.child, slave.prev = slave, master
    return master
}
```
　　The merge action itself is very direct: compare the two roots, then hang the larger tree at the front of the smaller root's child list. Unlike a binomial heap, there is no need to inspect tree order first.

## Taking It Easy
　　Just like a binomial heap, insertion into a pairing heap is also done by merging in a one-element heap.

　　When we want to change the value of a certain node, we can detach the subheap rooted at that node and merge it back in again.
```go
func (hp *Heap[T]) FloatUp(node *Node[T], value T) {
    if node != nil && value < node.key {        //only one-way updates; for a min-heap this means decreasing the key
        node.key = value
        if super := node.prev; super != nil && super.key > value {
            node.prev = nil
            if super.next == node {             //super is a sibling
                super.next, node.next = super.hook(node.next), nil
            } else {                            //super is the parent
                super.child, node.next = super.hook(node.next), nil
            }
            hp.root = merge(hp.root, node)
}   }   }
```
　　All of these operations take only `O(1)` time, but they also make the heap's storage structure messy, so eventually cleanup is required. The strategy of the pairing heap is obvious: defer the debt during ordinary operations, and pay it back in one batch when the heap top is actually removed.

## Catching Up
　　If one keeps living on borrowed time, repayment eventually comes due. After deleting a node, we must reorganize the subheaps it leaves behind before they can be merged back into the original heap.

　　One option is to perform cleanup by pairing siblings two by two, which completes the job in `O(N)` time.
```go
func collect[T cmp.Ordered](head *Node[T]) *Node[T] {
    if head != nil {
        for head.next != nil {
            list, knot := head, fakeHead(&head)
            for list != nil && list.next != nil {       //pair them two by two
                master, slave := list, list.next
                list = slave.next
                knot.next = merge(master, slave)
                knot = knot.next
            }
            knot.next = list
        }
        head.prev = nil
    }
    return head
}
```
　　Another option is first to pair, and then fold the results from right to left. This is more effective for well-organized sequences such as those in a binomial heap. That is exactly the version used in the current implementation.
```go
func collect[T cmp.Ordered](head *Node[T]) *Node[T] {
    if head != nil && head.next != nil {
        list, last := head, fakeHead(&head)
        for list != nil && list.next != nil {           //pair them two by two
            master, slave := list, list.next
            list = slave.next
            last.next = last.hook(merge(master, slave))
            last = last.next
        }
        head.prev = nil
        if list == nil {
            head, list = last, last.prev
        } else {
            head, list = list, last
        }
        for list != nil {                               //fold toward the right
            last, list = list, list.prev
            head = merge(head, last)
        }
        head.next = nil
    }
    if head != nil {
        head.prev = nil
    }
    return head
}
```
　　In fact, cleanup reaches `O(N)` only in the worst case. Its average complexity is at the `O(logN)` level.
