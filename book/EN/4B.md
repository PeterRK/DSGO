# Red-Black Trees
　　A red-black tree is also a balanced binary search tree, and together with the AVL tree it forms a kind of famous pair, though historically the red-black tree may be more deeply connected with B-trees.

　　Red-black tree nodes also carry a balancing attribute:
```go
type node[T cmp.Ordered] struct {
    key    T
    black  bool         //balancing bit
    parent *node[T]
    kids  [2]*node[T]
}
```
　　Since that balancing attribute is only 1 bit, it can be merged with the `parent` field:
```go
type node[T cmp.Ordered] struct {
    key   T
    trait uintptr       //compressed field
    kids  [2]*node[T]
}
func (unit *node[T]) setParent(parent *node[T]) {
    pt := uintptr(unsafe.Pointer(parent))
    if (pt & HackBit) != 0 {
        panic("unexpected high pointer")
    }
    unit.trait = pt | (unit.trait & HackBit)
}
func (unit *node[T]) getParent() *node[T] {
    pt := unit.trait & ^HackBit
    return (*node[T])(unsafe.Pointer(pt))
}
func (unit *node[T]) isRed() bool {
    return (unit.trait & HackBit) == 0
}
func (unit *node[T]) isBlack() bool {
    return (unit.trait & HackBit) != 0
}
func (unit *node[T]) setRed() {
    unit.trait &= ^HackBit
}
func (unit *node[T]) setBlack() {
    unit.trait |= HackBit
}
```
　　The so-called "balance factor" here is no longer an AVL-style height difference. It is merely color information. The code goes one step further and packs that color bit into the spare bits of the parent pointer, eliminating one standalone field.


## The Art of Watering Down
　　Unlike the dead-serious AVL tree, the red-black tree follows a more slippery path. Do we want a balanced tree? Fine: first imagine a perfectly balanced tree whose root-to-leaf paths are all of equal length. Let us call it a black tree. But a black tree is too perfect, and it is hard to squeeze anything useful out of that perfection. So we decide to water it down. The extra nodes we inject are called red nodes, and once watered down, the black tree becomes a red-black tree.  
　　Of course, there are rules to watering things down. It is a bit like transitional frames in video depending on key frames: in a red-black tree, red nodes are allowed to appear only after black nodes. This guarantees that the longest path in the tree (alternating red and black) is no more than twice as long as the shortest path (all black), which has a striking family resemblance to AVL balancing.

## Insertion and Rebalancing
　　As just described, insertion adds a red node. If the new node is attached after a black node, everything is fine. Otherwise, we must distinguish two cases according to the color of its uncle.
```
-----------Red Uncle-----------
=      bG      |      rG      =
=     /  \     |     /  \     =
=   rP    rU   |   bP    bU   =
=   |          |   |          =
=   rC         |   rC         =
```
　　When the uncle is red, recoloring the parent generation and the grandparent is enough. The grandparent, however, may then require further coordination with the great-grandparent, so the number of recolorings can reach `O(logN)`.
```
----------------LR Case----------------    ----------------LL Case----------------
|        bG        |        bC        |    |        bG        |        bP        |
|       /  \       |       /  \       |    |       /  \       |       /  \       |
|     rP    bU     |     rP    rG     |    |     rP    bU     |     rC     rG    |
|    / \           |    / \    / \    |    |    /  \          |          /  \    |
|      rC          |       u  v   bU  |    |  rC    x         |         x    bU  |
|     /  \         |                  |
|    u    v        |                  |
```
　　When the uncle is black, the relation among three generations yields four cases. By symmetry, we only analyze two, and both can be resolved by a single rotation.
```go
func (tr *Tree[T]) rebalanceAfterInsert(P *node[T], trace uint64) {
    for P.isRed() {                     //violates the double-red rule
        G := P.getParent()              //must exist; root is black, and P is not the root
        super := G.getParent()
        Pside := (trace >> 1) & 1
        Uside := 1 - Pside
        U := G.kids[Uside]
        if U != nil && U.isRed() {      //red-uncle pattern, solve by recoloring
            P.setBlack()
            U.setBlack()
            if super != nil {
                G.setRed()
                P = super
                trace >>= 2
                continue                //trace upward and recheck the double-red rule
            }                           //stop at the root
        } else {                        //black-uncle pattern, solve by rotation
            var root *node[T]
            if (trace & 1) == Pside {   //LL(RR)
                G.kids[Pside] = G.Hook(P.kids[Uside])
                P.kids[Uside] = P.hook(G)
                root = P
            } else {                    //LR(RL)
                C := P.kids[Uside]
                P.kids[Uside] = P.Hook(C.kids[Pside])
                G.kids[Pside] = G.Hook(C.kids[Uside])
                C.kids[Pside], C.kids[Uside] = C.hook(P), C.hook(G)
                root = C
            }
            G.setRed()
            root.setBlack()
            if super == nil {
                tr.root = super.hook(root)
            } else {
                super.kids[(trace>>2)&1] = super.hook(root)
            }
        }
        break                           //loop only when recoloring
}   }
```
　　As we can see, insertion in a red-black tree is more often about recoloring, while rotation is used only when a local structure looks wrong. That is also why deletion in a red-black tree usually requires less structural repair than deletion in an AVL tree.

## Deletion and Rebalancing
```go
func (tr *Tree[T]) Remove(key T) bool {
    //...
    if root := victim.getParent(); root == nil {
        //...
    } else {
        //...
        if victim.isBlack() {                           //red victims can be deleted freely; black ones require care
            if orphan != nil && orphan.isRed() {
                orphan.setBlack()                       //a red child turns black and takes over
            } else {                                    //remaining case: victim black, orphan also black
                tr.rebalanceAfterRemove(root, trace)    //in this case victim's sibling must exist
        }   }
        target.key = victim.key
    }
    return true
}
```
　　Deletion in a red-black tree is really about preserving black nodes. When the deleted node or its orphan is red, there is not much to worry about. Otherwise we need a more elaborate rearrangement.
```
---------------Red Uncle---------------
=        bG        |        bU        =
=       /  \       |       /  \       =
=     bO    rU     |     rG    bZ     =
=          /  \    |    /  \          =
=        bY    bZ  |  bO    bY        =
```
　　When the orphan's uncle is red, direct handling is awkward, but one rotation can turn the situation into one with a black uncle.
```
--------------Double Black-------------
|        xG        |        bG        |
|       /  \       |       /  \       |
|     bO    bU     |     bO    rU     |
|          /  \    |          /  \    |
|        bY    bZ  |        bY    bZ  |

---------------Middle Red--------------
|        xG        |        xY        |
|       /  \       |       /  \       |    ---------Inner Black, Outer Red--------
|     bO    bU     |     bG    bU     |    |        xG        |        xU        |
|          /  \    |    /  \  /  \    |    |       /  \       |       /  \       |
|        rY    xZ  |  bO   u  v   xZ  |    |     bO    bU     |     bG    bZ     |
|       /  \       |                  |    |          /  \    |    /  \          |
|      u    v      |                  |    |        bY    rZ  |  bO    bY        |
```
　　When the orphan's uncle is black, the colors of its cousins give three classes of cases: double black, middle red, and middle black with outer red. Double black can be solved by recoloring; if the color of the grandparent changes during that process, a chain reaction may continue upward. The other two cases both require one rotation. The red-uncle transformation never produces the double-black case, so the total number of rotations in the entire deletion process never exceeds two (`O(1)`, unlike the `O(logN)` behavior of AVL trees), although the number of recolorings may still reach `O(logN)`.

```go
func (tr *Tree[T]) rebalanceAfterRemove(G *node[T], trace uint64) {
    for {
        super := G.getParent()
        Oside := trace & 1
        Uside := 1 - Oside
        U := G.kids[Uside]                      //U != nil
        Y, Z := U.kids[Oside], U.kids[Uside]    //under a red uncle, both must be real black nodes
        if U.isRed() {                          //red-uncle pattern
            G.kids[Uside] = G.hook(Y)
            U.kids[Oside] = U.hook(G)
            U.setBlack()
            G.setRed()
            if super == nil {
                tr.root = super.hook(U)
            } else {
                super.kids[(trace>>1)&1] = super.hook(U)
            }
            trace = (trace << 1) | Oside
            continue                            //first turn it into a black-U case
        }
        var root *node[T]
        if Y == nil || Y.isBlack() {
            if Z == nil || Z.isBlack() {        //double black, solve by recoloring
                U.setRed()
                if G.isRed() {
                    G.setBlack()
                } else if super != nil {
                    G = super
                    trace >>= 1
                    continue                    //trace upward
                }
                break
            }
            G.kids[Uside] = G.Hook(Y)
            U.kids[Oside] = U.hook(G)
            U.copyColor(G)
            G.setBlack()
            Z.setBlack()
            root = U                            //middle black, outer red
        } else {                                //middle red
            G.kids[Uside] = G.Hook(Y.kids[Oside])
            U.kids[Oside] = U.Hook(Y.kids[Uside])
            Y.kids[Oside], Y.kids[Uside] = Y.hook(G), Y.hook(U)
            Y.copyColor(G)
            G.setBlack()
            root = Y
        }
        if super == nil {
            tr.root = super.hook(root)
        } else {
            super.kids[(trace>>1)&1] = super.hook(root)
        }
        break                                   //only special cases need a loop
}   }
```
　　The philosophy of the red-black tree is not to keep the shape as tightly stretched as an AVL tree. Instead, it tolerates a certain amount of uneven rise and fall, as long as the black skeleton remains sufficiently even.
