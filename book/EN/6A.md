# Kruskal's Algorithm
　　Kruskal's algorithm is a classical algorithm for the minimum spanning tree problem. Its idea is fairly direct: traverse all edges from small weight to large weight, and keep an edge whenever it is useful. Viewed globally, the algorithm gradually connects all vertices in the graph by means of the selected edges.

## Arrays + Linked Rings
　　The real difficulty here lies in recording and maintaining connectivity. We choose a hybrid structure made of arrays and singly linked rings: from the array side, we can quickly locate the record of any numbered vertex; from the singly linked ring side, we can quickly merge two connected components.
```go
type node struct {
    next *node          //points to the next vertex in the component, forming a singly linked ring
    mark int            //a positive value means the component id (the first vertex of the component)
}                       //a negative value means the number of vertices in the component whose head is this vertex
```
　　We use an id to record which connected component a vertex belongs to, and in the record of the vertex with the same id we store the number of vertices inside that component.

## Implementation & Analysis
　　First, sort the input edges so that they can be traversed from small weight to large weight. Then regard each vertex as its own connected component, and gradually merge components until one component contains every vertex. During this process, we always merge the smaller component into the larger one.
```go
func Kruskal_v2(roads []graph.Edge, size int) (uint, error) {
    if size < 2 || len(roads) < size-1 { return 0, errors.New("illegal input") }
    sort.Less[graph.Edge](edgeLess).Sort(roads)         //sort the edge set

    nodes := make([]node, size)
    for i := 0; i < size; i++ {                         //initialize vertex records
        nodes[i].mark, nodes[i].next = -1, &nodes[i]
    }
    trace := func(id int) int {
        if nodes[id].mark < 0 {
            return id
        } else {
            return nodes[id].mark
    }   }

    sum := uint(0)
    for _, path := range roads {
        active, another := trace(path.A), trace(path.B)
        if active == another {
            continue
        }
        sum += path.Weight                              //take this edge

        if -nodes[active].mark < -nodes[another].mark {
            active, another = another, active
        }
        nodes[active].mark += nodes[another].mark       //merge small into large

        tail := nodes[active].next                      //the two connected components
        nodes[active].next, nodes[another].next = nodes[another].next, tail
        for u := nodes[active].next; u != tail; u = u.next {
            u.mark = active
        }

        if -nodes[active].mark == size { return sum, nil }
    }
    return sum, errors.New("isolated part exist")
}
```
　　Let `E` be the number of edges and `V` the number of vertices. Sorting edges takes `O(ElogE)`, and traversing edges takes `O(E)`. The connectivity operations themselves are on the order of `O(VlogV)`. Since `E` is obviously no smaller than `V`, the overall complexity is `O(ElogE)`.

　　Let us look more closely at the complexity of the connectivity operations:
```
Let f(X) be the worst-case complexity of connectivity operations, and let A be a coefficient no greater than 1/2. Then:
f(X) = MAX( f(AX) + f((1-A)X) + AX )
If f(X) = O(XlogX), then:
f(AX) + f((1-A)X) + AX = X(logX + (AlogA + (1-A)log(1-A) + A))
Let B = 1/A >= 2, then:
AlogA + (1-A)log(1-A) + A = A((1 - ( logB + (B-1)log(1/(1-A)) )
Since B-1 > 0 and 1/(1-A) > 1:
logB + (B-1)log(1/(1-A)) > logB >= 1
Therefore:
AlogA + (1-A)log(1-A) + A <= 0
Thus:
f(AX) + f((1-A)X) + AX <= XlogX
Finally, by easy induction, f(X) = O(XlogX) holds
```
