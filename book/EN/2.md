___
　　A linked list is a sequential structure whose basic role is similar to that of an array. It does not support random access and therefore loses badly to arrays in searching, but it handles insertion and growth precisely where arrays suffer most, and does so in `O(1)` time.

　　Arrays excel at locating positions directly by index; linked lists excel at rewiring connections in place along a chain. Both can express linear structure. The difference is that one compresses the relationships into contiguous storage, while the other writes them explicitly into pointers, and as a result the operations they are good at are very different.

```go
type Node[T any] struct {
    Next *Node[T]
    Val  T
}

//fake_head -> [next|...] -> first_node
//              head      -> first_node
func FakeHead[T cmp.Ordered](spt **Node[T]) *Node[T] {
    return (*Node[T])(unsafe.Pointer(spt))
}

func Merge[T cmp.Ordered](lst1, lst2 *Node[T]) (list *Node[T]) {
    last := FakeHead(&list)
    for {
        last.Next = lst1
        if lst2 == nil {
            return list
        }
        for lst1 != nil && lst1.Val <= lst2.Val {
            last, lst1 = lst1, lst1.Next
        }
        last.Next = lst2
        if lst1 == nil {
            return list
        }
        for lst2 != nil && lst1.Val > lst2.Val {
            last, lst2 = lst2, lst2.Next
}   }   }
```
　　When operating on list nodes, one can use a trick often called a "fake node" or sentinel-like pseudo-node to simplify the expression of updates.

　　The so-called fake node does not mean we truly allocate an extra business node. Instead, we temporarily borrow the location that stores the head pointer, so that "modifying the head pointer" and "modifying the next pointer of an ordinary node" can be written in the same way. Operations such as merging or deletion, which would otherwise keep checking whether they are touching the first node, become much easier to write.

## Doubly Linked Lists and Rings

　　A list may also have more than one chain. If it has two chains in opposite directions, then it is a doubly linked list. We usually package the head pointer and tail pointer of a doubly linked list into one fake node (a ring knot), so that the list becomes a linked ring.
```go
type node struct {
    prev, next *node
}
type ring struct {
    node
}

func (r *ring) init() {
    r.prev = &r.node
    r.next = &r.node
}
```

　　Once the head and tail are connected back to this ring knot, the empty list, the first node, and the last node all fall under the same connection rules, and many boundary cases lose an entire branch of special handling.

　　The greatest practical advantage of a doubly linked list is that deletion becomes particularly convenient:

```go
func (n *node) Release() {
    n.next.prev = n.prev
    n.prev.next = n.next
}
```
　　As long as we already hold the target node in our hand, deletion no longer needs to search again from the head of the list for its predecessor. That is the most direct advantage of a doubly linked list over a singly linked list.
