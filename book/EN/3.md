## Hash Functions
　　The secret behind extremely fast lookup is to map the target object into an array, with the position inside that array computed from the object's content. A function that computes such an index is called a hash function.
```go
func Hash32(seed uint32, str string) uint32 {
    code := seed

    m := len(str) % 4
    for i := 0; i < len(str)-m; i += 4 {
        w := getU32(str[i:])
        w *= 0xcc9e2d51
        w = (w << 15) | (w >> 17)
        w *= 0x1b873593
        code ^= w
        code = (code << 13) | (code >> 19)
        code += (code << 2) + 0xe6546b64
    }
    if m != 0 {
        w := uint32(0)
        for i := len(str) - 1; i >= len(str)-m; i-- {
            w = (w << 8) | uint32(str[i])
        }
        w *= 0xcc9e2d51
        w = (w << 15) | (w >> 17)
        w *= 0x1b873593
        code ^= w
    }
    code ^= uint32(len(str))
    code ^= code >> 16
    code *= 0x85ebca6b
    code ^= code >> 13
    code *= 0xc2b2ae35
    code ^= code >> 16
    return code
}
```
　　A hash function tries to convert non-integer content such as strings into an integer. Taking that number modulo the array length yields a definite landing position. Those computed landing positions may conflict, and how to resolve such conflicts is the central topic of this chapter.

　　So the real problem a hash table has to face is not "how do we compute an integer," but rather "what do we do when many elements all want to land in the same place?" The main differences between the following sections lie precisely in how they handle that conflict.
